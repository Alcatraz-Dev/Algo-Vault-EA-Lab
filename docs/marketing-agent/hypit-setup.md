# Marketing Agent — Hypit Setup, Rendering & Workers

Hypit ([github.com/hypit-ai/hypit](https://github.com/hypit-ai/hypit)) is the
production/composition engine for the Marketing Agent. AlgoVault keeps the
project, the composition document, and every intermediate artifact; Hypit
compiles them into video.

---

## 1. What Hypit receives

The adapter (`lib/marketing-agent/hypit/provider.ts`) drives the Hypit CLI:

```
hypit --version        # version gate (see §2)
hypit doctor           # runtime health
hypit check <svml>     # validate markup before spending a render
hypit plan <svml>      # produce an execution plan (previewable, editable)
hypit build <svml>     # render
hypit status / get / cancel
```

Inputs are generated by AlgoVault, not by Hypit:

* **SVML document** — `hypit/svml.ts` renders the persisted
  `CompositionDocument` as `<?svml using="@hypit/markup@1"?>` markup: canvas,
  timeline items (with capture sources), caption cues, voice + music tracks
  (music ducked `ducking="music"` under voice), motion layer, brand logo,
  demo-label watermark, disclaimer, and the `render:Output` target.
* **Run Source** — `<?svml using="@hypit/run-markup@1"?>` with
  `<svrun version="1"><author source/><target output="final.video"/></svrun>`.
* **Assets** — browser captures, brand kit, voice/music files, thumbnails,
  referenced by stable ids.
* **Platform requirements** — aspect ratio, duration, safe zones, caption
  style; `recompose()` produces a per-aspect composition rather than a crop.

The **editable system of record is the `CompositionDocument` JSON**, not the
MP4. Persisting it means any version can be re-rendered, localized, or
recomposed later without redoing production (§11 of the brief).

## 2. Version pinning (§12, §85)

Production never depends on an unpinned `latest`:

```ts
// lib/marketing-agent/provider-constants.ts
export const EXPECTED_HYPIIIT_VERSION = "0.1.0";
export function isVersionCompatible(detected: string | null, expected?): boolean
```

* `isVersionCompatible` requires the **same major version** and a **minor
  version ≥ expected**. A missing or unparseable version is incompatible —
  the provider fails closed with a diagnostics entry instead of rendering.
* The detected version is surfaced through the provider's `diagnostics()` and
  asserted by tests (`test:marketing-agent`).
* **Upgrade path**: bump `EXPECTED_HYPIIIT_VERSION`, run `hypit doctor` +
  `hypit check` on an existing SVML, render one known-good project, verify
  output, then deploy. Never auto-upgrade production.

## 3. Health check (§84)

`hypit provider.health()` (and `doctor`) answers:

| Status | Meaning |
| --- | --- |
| `CONNECTED` | CLI present, version compatible, workspace writable |
| `DISABLED` | `MARKETING_HYPIT_ENABLED=false` (feature flag off) |
| `NOT_CONFIGURED` | CLI path missing / version incompatible |
| `ERROR` | binary or workspace failure (details in diagnostics) |

Browser, renderer, storage and social-account health are reported alongside it
(the growth cron refreshes social health every tick and records
`healthyAccounts`). All statuses render in the admin UI — `NOT_CONFIGURED`
is shown honestly, never hidden.

## 4. Feature flag & rollback (§90)

`MARKETING_HYPIT_ENABLED=false` (or the admin setting) disables Hypit
production **without touching** Growth, Marketing Factory, existing creative
tools, campaign analytics, or workflow nodes. The flag is checked at the
provider boundary; jobs degrade to a clear `NOT_CONFIGURED` state.

## 5. Rendering & the worker question (§83)

Rendering is deliberately **outside the request path**:

* HTTP routes only create/queue jobs (`app/api/admin/marketing-agent/*`).
* All long-running work (capture, render, QA, publish, analytics) executes in
  the **cron tick** — `/api/growth/cron/marketing-agent`, every 5 minutes —
  through the existing growth job runner (`lib/growth/jobs`). Jobs are
  idempotent, resumable, observable, and cancelable, and each carries
  `jobId / campaignId / creativeId / userId / provider / stage / status /
  timestamps / duration / retryCount / errorCode` (§88).
* Task and job timeouts (`taskTimeoutMs = 15 min`) bound a hung render so the
  next tick can resume rather than deadlock.

**Deployment target reality check**: a serverless request must not hold a
video render. On Vercel, the cron function runs the orchestration, and the
actual Hypit/ffmpeg work must execute where those binaries exist — either:

1. a self-hosted / persistent worker running the same cron entrypoint
   (`HYPIIIT_CLI_PATH`, `FFMPEG_PATH`, writable `MARKETING_AGENT_WORKSPACE`), or
2. the app deployed to a container host with those binaries installed.

If neither is available, keep `MARKETING_HYPIT_ENABLED=false`: planning, QA,
copy, scheduling and publishing still work; renders report `NOT_CONFIGURED`
instead of faking success (§91).

## 6. Workspace layout

```
MARKETING_AGENT_WORKSPACE (default /tmp/marketing-agent)
├── projects/<projectId>/composition.json   # editable document (source of truth)
├── projects/<projectId>/main.svml          # SVML document
├── projects/<projectId>/run.svml           # run source
├── projects/<projectId>/renders/<aspect>-<lang>.mp4
├── captures/<captureId>/…                  # sanitized frames/segments
└── thumbs/<versionId>.jpg
```

The workspace must be writable by the worker process and survive between
ticks for resumable jobs (on serverless, use durable storage or accept
re-render on cold starts — the document, not the file, is the record).

## 7. Troubleshooting

| Symptom | Check |
| --- | --- |
| Provider `NOT_CONFIGURED` | `HYPIIIT_CLI_PATH` set? `"$HYPIIIT_CLI_PATH" --version` runs? |
| Version gate fails | detected vs `EXPECTED_HYPIIIT_VERSION` (major must match) |
| `hypit check` rejects SVML | run `hypit check` on `main.svml`; the document JSON is intact — fix the renderer, never hand-edit markup |
| Render stalls | `hypit status`; check task timeout + workspace disk |
| Ducking/asset missing | composition must contain both voice and music; asset ids must exist |
| Rollback needed | set `MARKETING_HYPIT_ENABLED=false` — everything else keeps working |
