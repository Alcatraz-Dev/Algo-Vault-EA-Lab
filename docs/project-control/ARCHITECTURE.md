## 1. High-level shape

AlgoVault is a **Next.js 16 (App Router) + React 19 + TypeScript 5 + Tailwind CSS v4** web platform with **Firebase (Authentication + Realtime Database only)** as the backing service, **Stripe** for subscriptions/licensing, **MQL5/MetaTrader 5** for trading gateway/EAs, **Twelvedata/TradingView/RealMarket/Biquote** for market data, and a multi-provider **AI router** for intelligence. The repo is plain npm (no workspaces are actually hoisted; `packages/design-tokens` is a standalone local package consumed as `@algovault/design-tokens`).

## 2. Frontend architecture

### Routing & layout
- App Router; `app/layout.tsx` is the root layout (Geist + Geist Mono fonts, structured data, theme-init script, PWA/extension/analytics hosts).
- Two primary shells: `components/layout/AppShell` (account + account-admin) and `components/layout/AppSidebarLayout` (admin). Exceptions documented in `ALGOVAULT_PROJECT_MEMORY.md` §D (e.g., `/trading` is standalone; `components/trading/AccountHeader` owns its own page-header).
- `components/theme/theme-init.tsx` injects `THEME_INIT_SCRIPT` (reads `localStorage['algovault-theme']`, toggles `light`/`dark` classes on `<html>`).

### Theming
- Tailwind CSS v4: `app/globals.css` defines a dual semantic scale (`:root` = dark, `.light` = light) mapping CSS variables `--background/--foreground/--card/--muted/--accent/--border/-color-*` and an inline `@theme` that aliases them to `--color-*` for the Tailwind layer.
- Brand accent: the deep graphite/dark neutral is the primary brand tone; amber/gold (`--accent`) is reserved for active states, the brand mark and flagship signal feature.
- `packages/design-tokens` (local package) is the source of truth for design tokens (colors, spacing, typography, radius, shadows, animation, breakpoints, z-index) with a React Native export surface.

### Client / server boundary
- `"use client"` only where interactivity/realtime state is required (e.g., `ProTerminalChart`, `AccountShell`, watchlists, live feeds).
- Server components remain the default everywhere else. API routes and server actions are the only privileged entry points for data writes.

## 3. Backend / data architecture

### Firebase (the only database)
- **RTDB only** — no Firestore and no migrations to Firestore.
- `lib/firebase-admin.ts` connects to RTDB via `NEXT_PUBLIC_FIREBASE_DATABASE_URL`.
- `database.rules.json` is the committed ruleset; gaps are documented (e.g., `users` has `indexOn` only for subscription id fields).
- Module `lib/candel/workspace/database.ts` is the canonical RTDB store for the Candel system (instances, templates, conversations, messages, memory, activity, approvals, automations, jobs, proposals, account bindings, permissions).

### Server-side privileged operations
- Every sensitive route validates the caller: `app/api/*` routes use `authenticate()` (`lib/admin-auth.ts`) or `validateApiKey()`; admin routes use `requireAdmin()` / `requireAdminOrProductOwner()`.
- Secrets are never exposed to clients: `NEXT_PUBLIC_*` is reserved for client-safe values only (Firebase config, app URL, bot username, Discord client id).

### API surface
- ~230 `route.ts` handlers. Cross-cutting concerns (auth, audit logging, idempotency, error envelopes) are repeated per route — there is **no centralized API gateway** yet. This is a P3/architecture improvement target.

## 4. Authentication & authorization

- `lib/admin-auth.ts`: `requireAdmin`, `authenticate`, `requireAdminOrProductOwner`.
- `lib/api-key-auth.ts`: `validateApiKey` (third-party / extension keys).
- `lib/plugins/api-helpers.ts`: `authUid` (plugin runtime), `PLUGIN_RUNTIME_CRON_SECRET` (cron).
- Public-by-design (no auth): home/marketing, economic calendar, market data reads, webhooks (Stripe/TradingView, secret-gated), EA-side license checks, some low-risk public pages.

### Known security hardening (already done, kept forever)
1. `/api/ai-signals/monitor/route.ts` gated with `x-cron-secret`/`CRON_SECRET`.
2. `/api/extensions/analysis/route.ts` validates `x-api-key` via `validateApiKey` (was presence-only).
3. `/api/alerts/check/route.ts` and `/api/trade-management/monitor/route.ts` were fail-OPEN; now fail-closed with the canonical `x-cron-secret`/`?secret=`/Vercel-cron pattern.
4. `/api/telegram-signals/webhook/route.ts` had a hardcoded fallback secret + `NODE_ENV !== "production"` bypass; hardcoded default removed, dev bypass is now explicit via `TELEGRAM_INGESTION_ALLOW_DEV=1`.

### Route auth matrix
Documented in `ALGOVAULT_PROJECT_MEMORY.md` §O (auth matrix). New routes must add an entry there before shipping.

## 6. Trading architecture

- **Execution mode** is DEMO-only. `TRADING_EXECUTION_MODE=DEMO` is the only supported value; all other values disable execution (fail-closed).
- **Unified trading service** (`lib/trading/unified/`) is provider-neutral. Providers: `MT5_DEMO_ENABLED` (the only enabled demo), others hard-off (`MT4_DEMO_ENABLED`, `CTRADER_DEMO_ENABLED`, `TRADINGVIEW_EXECUTION_ENABLED`, `ALGOVAULT_BROKER_ENABLED`, `LIVE_TRADING_ENABLED`).
- Gateway: `/api/trading/gateway/*` (token minted at `/api/trading/gateway/token`); EAs run locally inside the user's MT5 terminal.
- **Safety gates** (fail-closed): server-side authorization, account ownership validation, environment validation, command idempotency, unique command identifiers, expiration/stale-command protection, execution acknowledgement, duplicate-order prevention, auditable event logs, safe disconnect handling, explicit error states, clear demo-mode labeling. Never report executed merely because a command was sent; distinguish requested/accepted/executed/rejected/unknown.
- Execution verification: wait for gateway execution report, then poll synced account state until the ticket appears. Out-of-timeout outcome is `EXECUTED_PENDING_SYNC` (HTTP 200, ticket kept in providerRef) — never `FAILED`, so a late snapshot can never invite a retry that would double a real position.

## 7. Market-data flow

```
Client (chart)  ──OHLC history──>  /api/market/quotes / /api/analytics/ohlc
                                      │
                                      ▼
                              Server-side source resolution (Twelve, TradingView, RealMarket, Biquote)
                                      │
                                      ▼
                              Canonical candle engine (lib/chart-engine):
                              normalize → aggregate → dedup → page → reconcile
                                      │
                                      ▼
                              Renderers: ProTerminalChart (native)
                                      + shared TradingChart/ChartEngine
```

- `useLiveCandles` (hooks) drives realtime: merges quotes into the forming bar, reconciles periodically against the provider, reports `live`/`stale`/`gap_detected`/`reconnecting`/`market_closed`.
- Overlays (EMA/SMA, VWAP, pivots, FVGs, order blocks, structure, GEX, AI overlays) are computed from the **same canonical candles** the chart renders, using the shared `lib/market-core` engines where applicable.

## 8. Intelligence & AI orchestration

- **AI Router** (`lib/ai/router.ts` + `lib/ai/providers/*`): multi-provider routing with dynamic model discovery, free-only guard, local heuristic fallback. Free-only policy is permanent (`AI_FREE_ONLY=true` default).
- **Market intelligence** (`lib/market-intelligence/`): structure detection, indicators, backtesting, validation, memory, research, smart-money (phase 4+.8), AI layers, providers (including TradingView MCP).
- **Candel system** (`lib/candel/`): workspace infrastructure, agent execution, intelligence context/evidence builders, templates, RTDB store, authorization.
- Deterministic engines are never replaced by an LLM when deterministic logic is more appropriate. Every conclusion distinguishes facts, measurements, interpretations, hypotheses, missing data, limitations, and risks. "WAIT" / "NO_TRADE" are first-class states, not forced BUY/SELL.

## 9. Payments & licensing

- **Stripe**: checkout, webhooks (`/api/webhooks/stripe`, signature-verified + idempotent), subscription lifecycle, entitlements, license creation/revocation, affiliate attribution, commission.
- **License model**: one licensing system (`lib/plugins/licensing.ts` + `app/api/license/*`). EA-side license validation is public by design; server-side entitlement checks are authoritative.
- Self-hosted marketplace: `app/api/products/*`, `/marketplace/*`, download endpoints. License issuance and entitlement synchronization must be idempotent and race-safe.

## 10. Admin architecture

- `components/layout/AppSidebarLayout` + `admin-nav.ts` own the admin shell. Sections: users, products, orders, subscriptions, licenses, affiliates, payments, trading integrations, system health, audit, config.
- Admin routes are server-only; privilege is checked server-side. No admin-exposed capability ships without a documented permission check.

## 14. Security boundaries

- Authorization is always server-side; client-side checks are UI-only.
- Webhooks are signature-verified and idempotent (Stripe, TradingView).
- Cron/monitor/ingestion endpoints fail-closed when their shared secret is unset.
- Secrets exist only server-side; `NEXT_PUBLIC_*` is never used for secrets.
- Trading commands require account ownership + environment + license verification before any execution path.
- No developer platform API exists yet (see `docs/project-control/` later phases).

## 15. Key decisions recorded (summary)

See `DECISIONS.md` in this directory for the full register. High-signal decisions already made:
1. **RTDB only** — no Firestore migration.
2. **Free-model-first policy** — `AI_FREE_ONLY=true` default; paid provider only on explicit authorization.
3. **DEMO execution only** — fail-closed; live trading is a separate, gated capability.
4. **Evidence-first intelligence** — facts/measurements/interpretations separated; WAIT/NO_TRADE are first-class.
5. **Server-side auth authority** — hiding a button is not authorization.
6. **Precedence: fix bugs before redesign** — no redesign without the reliability and chart gates first.
7. **Design tokens as source of truth** — `packages/design-tokens` + CSS variable scale in `app/globals.css` (dark + light, same architecture).
