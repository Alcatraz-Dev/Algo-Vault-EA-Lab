AlgoVault is a production-intent traffic trading platform combining:
- **Strategy Lab** — backtest engine (EA Lab), walk-forward, Monte Carlo, equity curve, report generator, strategy marketplace.

## §K. AI Router & Bytez Integration (canonical)

### Architecture
`lib/ai/router.ts` (class `AIRouter` + exported `defaultRouter`) manages a `Map<providerId, AIProvider>`. Fixed fallback order: Gemini → OpenRouter → OpenCode → B.AI → **Bytez** → Local heuristic (`lib/ai/local.ts`). Free-only guard `assertFreeModelAllowed` in `lib/ai/models.ts` blocks paid models unless a paid budget is allowed. Dynamic model discovery per provider via `getModels()`; `getAllModels()` aggregates and falls back to `KNOWN_FREE_MODELS` on total failure. Bytez joins the chain whenever `BYTEZ_API_KEY` is configured: under `AI_FREE_ONLY=true` (default) only `meter`-`*-free` models are served, and when a paid budget is allowed (`AI_FREE_ONLY=false`) its chat default is the first enabled discovered model (never a hardcoded catalog). `getAIProvider()` mirrors the provider chain (gemini → openrouter → opencode → bai → bytez).

### Provider interface (implement in `lib/ai/providers/*`)
`id`, `name`, `isAvailable()`, `getModels(): Promise<AIModel[]>`, `chat(req): Promise<AIResponse>`, plus optional `describeStrategy`/`summarizeAnalysis`. Register in `AIRouter` constructor and in `getAvailableCloudProviders()` (and ensure `getAllModels()` covers it — it iterates `this.providers.values()`, so constructor registration is enough).

### Bytez provider (`lib/ai/providers/bytez.ts`) — the real integration
- Base URL: `https://api.bytez.com`. Chat: `POST /models/v2/openai/v1/chat/completions` (OpenAI-compatible: `{model, messages:[{role,content}], max_completion_tokens, temperature}`).
- **Auth header is `Authorization: <BYTEZ_API_KEY>` RAW — no `Bearer` prefix.** 401 → `INVALID_API_KEY`, **402 → `QUOTA_EXCEEDED`** (credit exhaustion), 429 → `RATE_LIMITED`.
- **Dynamic discovery (never hardcode model lists):** `GET /models/v2/list/tasks` → `{error, output: string[]}`; `GET /models/v2/list/models?task=<task>` → `{error, output: [{meter, meterPrice, modelId, params, ramRequired, task}]}`. Use tasks to pick the right catalog (chat, code, etc.).
- **Free tier honesty:** Bytez is credit-based, NOT free. `meter` ending `-free` = free-eligible. Everything else is paid/metered and MUST be blocked when `AI_FREE_ONLY=true`. Do not label Bytez models "free" in the UI unless `meter` ends in `-free` (verified).
- `isAvailable()` returns true only when `BYTEZ_API_KEY` is set (server-side only; never hardcoded; never crash when missing).
- `.env.example` documents `BYTEZ_API_KEY`.

### Reference provider template
`lib/ai/providers/openrouter.ts` is the closest template (error mapping, timeout via `AIConfig.timeoutMs`, finish-reason mapping in `lib/ai/finish.ts`).

## §L. Signals System (canonical)

- `lib/ai-signals/` — monitor, engine, quality-filter, lifecycle-engine, stale-detection, price-sanity, confidence, tiers, sessions-filter, symbol-specs, freshness-guard, access, notify, events, analytics, statistics, results.
- Signals are computed deterministically from Biquote OHLC + Xoomar sentiment (news), then quality-filtered — **no random directions**. The old `Math.random()` direction in `features/telegram-signals/generator/ai-signal-generator.ts` was replaced with a deterministic rule. Do not reintroduce randomness.
- **Signals system limits (updated 2026-09-28):** free tier = **10 AI signals/day**, pro tier = **20 AI signals/day**. Canonical source: `loadSignalConfig()` default in `lib/ai-signals/engine.ts` (mirrored in `app/admin/signals/page.tsx` defaults + UI hints on `/signals` and `/signals/stats`). Admin can change per day via Admin → Signals config (`signalConfig/default` in RTDB). AI signals are deterministic (Biquote OHLC + sentiment → quality filter), generated on demand via "Scan" (`POST /api/ai-signals`).
- **Pro/Telegram signal pipeline (verified 2026-09-28):** Pro signals are **Telegram-sourced**, not AI-generated. Admin MTProto client (`features/telegram-signals/connectors/telegram-client-manager.ts`) watches enabled channels, calls `processIncomingTelegramMessage({ userId: "system", broadcast: true })` → signal saved to `telegramSignals/system` (id `sig_<ts>_<rand>` from `signal-normalizer.ts`) and broadcast to Pro users' own `telegramSignals/{uid}` nodes. `/api/pro-signals` GET merges system + user nodes **deduped by id** (user copy wins), and `RealtimeFeed.tsx` applies the same dedupe on the RTDB path — both are required because mirrored copies previously produced duplicate React keys (console warning `Encountered two children with the same key sig_…`, first fixed 2026-09-27 session). Follow/trade/execute write into `telegramSignals/{uid}`; `/api/signals/auto-update` sweeps Pro signals via `saveProSignal` (sanitized for RTDB) + `transitionSignalState`.
- Execution tickets: real gateway-provided tickets only. The fake `#EXE-<random>` tickets in `lib/copy-trading.ts`, `features/telegram-signals/gateway/gateway-adapter.ts`, and `app/api/signals/execute/route.ts` were replaced with honest "submitted/pending" states and real gateway tickets. If a path still fakes a ticket, fix it.
- **`/api/signals/execute` is now authenticated (2026-09-28):** previously a fully unauthenticated route that queued real MT5 orders into `mt5_orders/{account}` — anyone could target an arbitrary account. It now requires `authenticate()` and resolves the MT5 account exclusively from the caller's connected `trading_accounts/{uid}` (body `mt5Account` is ignored; optional `productId` still scopes the position path). Do not regress to body-supplied accounts.
- Price sanity (`lib/ai-signals/price-sanity.ts`): per-instrument % thresholds against the live quote. FX majors use **0.05%** (≈5 pips on EURUSD). Do not tighten FX back to 0.01% — that rejects nearly every real signal (entry prices naturally differ by a few pips from the live quote).
- Tests: `lib/ai-signals/__tests__/run-ai-signals-tests.ts` (price sanity, lifecycle, monitor) — run via `node scripts/jiti-tsrun.mjs` (needs tsconfig `@/` path + env resolution).
- **Realtime pricing across the signals domain (2026-09-28):** `/api/signals/quotes` now resolves every symbol through `tradingViewLivePriceCache` (shared resolver: fresh Biquote forming M1 candle → TradingView scanner; 5 s server cache + in-flight dedupe) and returns `prices` + `quotes` metadata (change/changePercent/provider/timestamp). `useLivePrices` defaults to 5 s polling (was 10 s), exposes `quotes`, and pauses while the tab is hidden. Signal pages (`/signals`, `/signals/pro`, `/signals/stats`, both `[id]` detail pages) and `SignalFeed` poll at 5 s. `SignalChart` is already live via `useLiveCandles` (history + 2 s quote-tick merge into the forming bar + 60 s reconcile) — do not fork a second chart feed. The SL/TP sweeps (`/api/signals/auto-update` AND `/api/pro-signals/auto-update`) now batch price lookups per symbol through the same resolver (was a serial `fetchCandles` M1 pull per signal) and `vercel.json` runs both every 2 min (was 5). Real-time SL/TP state therefore propagates to clients within ~2 min via cron + on-demand via the pages' Scan/15 s refresh loops.

## §AH. Pine Runtime Backtest Engine — Fixed 2026-09-22 (was failing at HEAD)

`node scripts/jiti-tsrun.mjs lib/strategy-lab/tests/run-tests.ts` FAILED at HEAD (`5ec3f45`); now passes 100%. Three distinct root causes, all in `lib/pine-runtime/`:

1. **Named order ids were discarded** — `strategy.entry("L", …)` never stored the order name, so `strategy.close("L")`/`strategy.exit("L")` (which match by name) could never fire → 0 closed trades. Fix: `StrategyTrade.entryId?: string` (types.ts), set it in the `entry` handler, match it in `exit`/`close` alongside the existing `id.includes` fallback (runtime.ts).
2. **Builtin field-access objects were unresolvable** — `barstate.islast`/`syminfo.*`/`timeframe.*` went through the generic `FieldAccess` case, which resolved the base Identifier via scope lookup only → `undefined` on every bar → `if barstate.islast …` never ran. Fix: the `FieldAccess` case now routes `barstate`/`syminfo`/`timeframe` through the same `getDefaultBarState`/`getDefaultSymbolInfo`/`getDefaultTimeframeInfo` sources the namespaced-call path uses (runtime.ts).
3. **Pine cost model was not applied** — `backtestPine` copied `t.pnl` (gross) into `profit`/metrics without spread/slippage/commission. Fix (backtest.ts): per-trade `net = gross − unitCostPerUnit × size` where `unitCostPerUnit = spreadPips·pipSize + slippagePips·pipSize·2 + commissionPerLot`, using `SYMBOL_SPECS` (`@/lib/ai-signals/symbol-specs`) for pip size (XAUUSD 0.01). Mirrors the Strategy Lab engine's convention where `profit == pnlGross == net`; `spreadCost`/`commission`/`slippageCost` are now reported on the Pine path too. Note: the Pine path deliberately does NOT multiply by `contractSize` — the test contract (`backtest.test.ts` blocks 3 & 5) defines these unit costs per engine-size unit.

**Test correction (not engine hack):** block 5 asserted profit against `candles[9]` (a bar index copied from block 3's 10-candle window) on a 12-candle run where `barstate.islast` = bar 11 — physically unsatisfiable; corrected to `candles[candles.length - 1]` with a comment. Block 3 (10 candles, last = index 9) was already consistent and passes unchanged.
